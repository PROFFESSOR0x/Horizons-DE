# تدقيق عميق: الـ dots وتكامل كل شل مع Hyprland

**تاريخ:** 2026-09-05
**الجزء الثاني** من تدقيق الشلّات — يكمل [quickshell-competitor-audit.md](quickshell-competitor-audit.md). المصادر نفسها (`/g/dotfiles/{Ax-Shell,Ambxst,caelestia-shell,axctl,hyprland-plugins}`، محليّة، مش جزء من هذا الـ repo).

**اكتشاف أول مهم:** الشلّات التلاتة عندها فلسفات مختلفة تمامًا في تسليم الـ dots نفسها:

| الشل | الـ Hyprland dots فين؟ |
|---|---|
| Ax-Shell | مرفقة جزئيًا في نفس الـ repo (`config/hypr/{hypridle,hyprlock}.conf`) — بس **بدون** `hyprland.conf` كامل، الشل بيلحق نفسه بإعداد المستخدم الموجود عبر سطر `source =` |
| Ambxst | **مفيش أي ملفات hypr خالص** في الـ repo — التكامل كله عبر daemon خارجي منفصل اسمه `axctl` (تفصيل كامل تحت) |

Horizons-DE على النقيض من التلاتة: بيشحن `hyprland.conf` كامل + كل ملفات الـ lua (general/keybinds/rules/env/execs/variables) كجزء أساسي من الـ repo نفسه (`dotfiles/dots/.config/hypr/`).

## 1. Ax-Shell: أبسط نمط تكامل (الأقرب لأسلوب Horizons-DE مع i3)

`config/settings_gui.py` عنده خيار GUI حرفي اسمه **"Auto-append to hyprland.conf"** — بيتأكد الأول إن السطر مش موجود أصلاً (`"Source string already present in hyprland.conf"`) قبل ما يضيفه، بالظبط نفس النمط اللي installer.sh بتاع Horizons-DE بيستخدمه لـ i3 (`grep -Fq 'include ...'` قبل الإضافة) **وكان بيستخدمه فعلاً لـ Hyprland نفسه قبل الجلسة دي**. الفرق الوحيد: Ax-Shell عنده toggle صريح في الواجهة الرسومية يقدر المستخدم يقفله لو عايز يضيف السطر يدويًا.

`hypridle.conf` بتاعه فيه خطوة Horizons-DE مالهاش مكافئ: **تعتيم الشاشة قبل القفل مباشرة** (`timeout=150 → brightnessctl -s set 10`) قبل الـ lock نفسه (`timeout=300`) — إشارة بصرية إن القفل قرّب، مش قفل مفاجئ. جدول التوقيتات بتاعه (2.5/5/5.5/30 دقيقة) أقصر شوية من Horizons-DE (5/10/15 دقيقة، بلا suspend مُجدول أصلاً — الـ 900s الوحيدة بتاعت Horizons هي suspend، مفيش تعتيم قبلها).

## 2. Ambxst + axctl: أعمق تكامل شافيته في التدقيق كله

### إيه هو axctl
مستودع منفصل تمامًا (`github:Axenide/axctl`)، مكتوب بلغة **Go**، عبارة عن:
> "a universal IPC daemon and CLI for Wayland compositors... normalizes window, workspace, monitor, layout, config, and system operations across **Hyprland, Niri, and Mango** via a JSON-RPC API over a Unix socket."

يعني: daemon واحد مستقل تمامًا عن أي شل، بيكتشف الـ compositor الشغال ({Hyprland,Niri,Mango})، ويوفّر:
- **API موحّد** (JSON-RPC عبر `/tmp/axctl-$UID.sock`) لأي حاجة تحب تتكلم معاه — مش مقصور على Ambxst، أي أداة تقدر تستخدمه.
- **CLI** (`axctl window list`, `axctl subscribe`, ...) — سطر أوامر جاهز.
- **كتابة الإعداد نفسه**: من الـ README الرسمي لـ Ambxst — *"`~/.local/share/ambxst/hyprland.lua` is regenerated by the `axctl` daemon on every theme/gaps/binds change"* — يعني الـ daemon هو اللي بيولّد ملف Lua الفعلي بتاع Hyprland من الإعدادات العليا (ثيم/gaps/keybinds)، مش الشل نفسه.

### التكامل من جانب QML
- `AxctlService.qml` (singleton) — عنده `clients`/`monitors`/`workspaces` كـ observable state (مُغذّاة من `axctl subscribe` حيًا، مش polling)، و`dispatch(command)`.
- **حيلة توافقية ذكية**: `dispatch()` بياخد سلسلة أوامر **بصيغة Hyprland الكلاسيكية بالظبط** (`workspace 3`, `closewindow address:0x...`, `focuswindow address:0x...`, `movetoworkspacesilent`, `focusmonitor`, `togglespecialworkspace`) ويترجمها داخليًا لصيغة axctl الموحّدة (`["window", "close", addr]`). النتيجة: أي كود QML مكتوب بافتراض "أنا بكلم Hyprland" بيشتغل حرفيًا من غير تعديل، لكن فعليًا بيتنفّذ عبر axctl، فيشتغل على Niri/Mango كمان بلا تغيير — توافق للخلف مع نمط الكود الشائع في مجتمع Hyprland/Quickshell، مع تعميم حقيقي تحت السطح.

### مقارنة مباشرة بـ WM.qml بتاع Horizons-DE (من تدقيق i3 السابق)

| | axctl (Ambxst) | WM.qml (Horizons-DE) |
|---|---|---|
| مكان التنفيذ | daemon خارجي مستقل (Go، عملية منفصلة) | داخل عملية Quickshell نفسها (QML، backends منفصلة لكل compositor) |
| الاتصال | JSON-RPC عبر Unix socket واحد، دائم | كل backend بيعمل subprocess (`hyprctl`/`i3-msg`) بنفسه، أو Quickshell.Hyprland المدمجة لجزء من hyprland فقط |
| الأنظمة المدعومة | Hyprland, Niri, Mango (3، بامتداد سهل لأي حد يضيف backend في Go) | Hyprland, Niri, i3 (Sway/Mango معلَّقين كـ TODO فعليًا في الكود — `// case "sway": ...`) |
| كتابة إعداد الـ compositor | axctl نفسه بيولّد الملف (theme/gaps/binds → hyprland.lua) | `hyprconfigurator.py` — سكربت بايثون منفصل، **Hyprland فقط**، مفيش أي مكافئ لـ i3/Niri config-writing |
| إعادة الاستخدام خارج الشل | نعم — أي أداة (bash script، شل تاني، status bar تاني) تقدر تستخدم نفس الـ daemon | لأ — الكود جوه Quickshell نفسه بس، مش قابل لإعادة الاستخدام من عملية تانية |

**الخلاصة:** axctl حلّ نفس المشكلة اللي `WM.qml`/`hyprconfigurator.py` بيحاولوا يحلّوها في Horizons-DE، لكن بفصلها في أداة مستقلة قابلة لإعادة الاستخدام عبر أي شل/أداة، مش مربوطة بمشروع QML واحد. ده استثمار هندسي (لغة تانية، مشروع منفصل، دورة صيانة منفصلة) أكبر بكتير من نطاق أي تعديل بسيط في Horizons-DE، لكنه **يستحق المتابعة كمصدر إلهام** — مش للنسخ، لكن كنموذج لو Horizons-DE حابب يوسّع دعم Niri/Sway بشكل أعمق مستقبلاً بدون ما يكرر منطق كل compositor داخل كل backend QML منفصل.

### PAM في Ambxst — تأكيد إضافي على توصية التدقيق السابق
`modules/lockscreen/LockScreen.qml` بيستورد `Quickshell.Services.Pam` ويستخدم `PamContext` مباشرة (نفس اكتشاف caelestia بالظبط)، مع ملف PAM مخصص مرفق (`config/pam/password.conf`: `auth required pam_unix.so` — أبسط من ملف caelestia بس نفس الفكرة: ملف pam.d خاص بالشل، مش الاعتماد على ملف النظام الجاهز). **شِلّان مستقلّان تمامًا، من مطورين مختلفين، الاتنين اختاروا نفس الحل** — ده يرفع مستوى الثقة إن `Quickshell.Services.Pam` هو المسار الصح فعلاً، مش مجرد اختيار شل واحد بالصدفة.

فيه كمان ملف تنفيذي مُجمّع اسمه `ambxst-auth` (ELF 64-bit، غير موثّق بوضوح حتى في AGENTS.md بتاعتهم نفسها — "`# Helper script (if any)`") — غرضه مش واضح من غير تحليل عكسي أعمق، فمينفعش يتفترض عليه حاجة بدون فحص إضافي.

## 3. hyprland-plugins (المستودع الرسمي)

| Plugin | الوصف | مستخدم في Horizons-DE؟ | ملاحظة |
|---|---|---|---|
| `hyprexpo` | Overview بأسلوب GNOME/KDE | لا | Horizons-DE عنده Overview مبني بالكامل في QML (`Overview.qml`) — بديل موجود أصلاً، مش فجوة |
| `hyprbars` | شريط عنوان بسيط لكل نافذة | لا | متعمَّد على الأغلب — الشل نفسه هو مصدر الـ chrome، مش عايزين شريط عنوان مزدوج |
| `hyprscrolling` | تخطيط تمرير (scrolling layout) بدل التقسيم التقليدي | لا | تغيير فلسفي كامل لطريقة التبليط، مش "إضافة" بسيطة — قرار كبير لو اتفكر فيه |
| `hyprwinwrap` | تضمين نافذة كخلفية حية (بديل xwinwrap) | لا | ممكن يبقى مفيد كبديل لـ mpvpaper الحالي لخلفيات الفيديو — يستاهل فحص منفصل |
| `borders-plus-plus` | حدود إضافية للنوافذ | لا | تجميلي بحت، أولوية منخفضة |
| `hyprtrails` | أثر حركة خلف النوافذ | لا | تجميلي بحت، المطورين أنفسهم واصفينه "useless but neat" |
| `csgo-vulkan-fix` | إصلاح خاص بألعاب معيّنة | لا | خارج نطاق شل سطح المكتب |
| `xtra-dispatchers` | dispatchers إضافية | لا | يستاهل فحص لو فيه dispatcher معيّن ناقص من نظام Lua الحالي |

**الخلاصة:** Horizons-DE مش بيستخدم أي plugin رسمي حاليًا (متسق مع إزالة `hyprglass` — plugin غير رسمي — بالكامل في وقت سابق من المشروع)، ومعتمد بالكامل على إعداد Hyprland الأصلي + الشل نفسه للتأثيرات البصرية والـ overview. الفجوة الوحيدة اللي تستاهل فحص فعلي هي `hyprwinwrap` (بديل محتمل لآلية الفيديو-خلفية الحالية القائمة على mpvpaper).

## 4. caelestia: الإشارة لمصدر منفصل (`caelestia-dots`)

الـ README الرسمي بتاع `caelestia-shell` بيوضّح صراحة: هذا الـ repo "الشل بس" — الـ dots (Hyprland config، hyprlock، إلخ) في مستودع منفصل تمامًا اسمه `caelestia-dots` (مش محمّل محليًا هنا، محتاج تحميل منفصل لو عايزين تدقيق فعلي على محتواه). كمان فيه أداة CLI منفصلة (`caelestia-cli`، من نفس التنظيم `caelestia-dots/cli`) — نفس فلسفة "شل + دوتس + CLI كل واحد في مستودعه" بتاعة Ambxst (`Ambxst` + `axctl`)، لكن caelestia بتفصل الـ CLI عن التحكم في الـ compositor نفسه (`axctl` بيعمل الاتنين، إدارة الـ compositor وكتابة إعداده).

## 5. توصيات إضافية (فوق توصيات المستند الأول)

1. **تأكيد بديل PAM (أولوية عالية، مُكرَّرة من المستند السابق لكن بدليل مضاعف الآن):** شِلّين مستقلّين (Ambxst وcaelestia) استخدموا `Quickshell.Services.Pam` مش سكربت shell — ده يرفّع أولوية فحصه فعليًا كبديل لـ `face-auth.sh`.
2. **`hyprwinwrap` كبديل محتمل لـ mpvpaper:** يستاهل فحص منفصل — ممكن يبسّط آلية خلفية الفيديو الحالية.
3. **axctl كمصدر إلهام معماري (مش نسخ مباشر):** لو دعم Niri/Sway هيتعمّق مستقبلاً في Horizons-DE، فكرة "طبقة IPC موحّدة مستقلة عن الشل نفسها" تستاهل إعادة نظر، بدل تكرار منطق كل compositor جوه كل backend QML.
4. **لا حاجة لتبني أي hyprland-plugin رسمي حاليًا** — القائمة اتفحصت كاملة ومفيش فجوة واضحة غير `hyprwinwrap` (بند 2).
5. **خطوة تعتيم قبل القفل** (نمط Ax-Shell's `hypridle.conf`): إضافة بسيطة ومنخفضة الخطورة لملف `hypridle.conf` بتاع Horizons-DE — تعتيم الشاشة (`brightnessctl -s set N`) في listener قبل خطوة القفل الفعلية، مع استرجاع السطوع (`on-resume`) لو المستخدم تفاعل قبل ما يوصل لمرحلة القفل.

# دراسة أداء Horizons DE وتنفيذ التحسينات

التاريخ: 8 سبتمبر 2026. هذه دراسة للكود وللنظام المحلي، مع تغييرات منفذة وتجارب قابلة للإعادة. القياسات ليست تقديرًا نظريًا ولا وعدًا بتحويل الواجهة إلى KDE أو GNOME في تغيير واحد.

## 1. النتيجة وحدودها

تم تطوير مسار الحصول على بيانات Hyprland داخل الشِل: طلبات socket مباشرة، وتجميع أحداث محدود الانتظار، وعدم تداخل الطلبات، وعدم إعادة نشر البيانات المتطابقة. وتم تطوير أخذ عينات موارد الجهاز، وتأجيل تحميل صفحات الشريط الجانبي، وتقليل العمل المتكرر في فهرس التطبيقات وبعض النصوص.

لم يتم تعديل أو استبدال الملف التنفيذي C++ لـQuickshell المثبت. التغييرات في قلب خدمات Horizons المبنية عليه، باستخدام مكوناته الأصلية، بعد مراجعة وثائقه وبعض مصدره C++. هذا التفريق مهم: استبدال خمس عمليات `hyprctl` باتصالات Qt المحلية تنفيذ فعلي داخل مسار QML/Qt، لكنه ليس fork جديدًا لمحرك Quickshell.

الأرقام تثبت تقليل كلفة طلب IPC والعمل الزائد وإطلاق العمليات؛ لا تثبت حتى الآن زيادة FPS أو انخفاضًا سببيًا محددًا في RAM أو CPU للبيئة كاملة. تجربة الخدمة القصيرة لم تظهر تحسنًا واضحًا في CPU/RAM. لن أستخدم نسبة تحسن IPC باعتبارها نسبة تحسن سطح المكتب كله.

## 2. البيئة وخط الأساس

- المعالج: Intel Core i7-8665U. بطاقة Intel مدمجة؛ لم تظهر واجهة `gpu_busy_percent` مدعومة في تجربة الحساسات، لذلك لا نعرض استخدام GPU وهميًا.
- Quickshell المثبت: 0.3.1، حزمة Arch Linux.
- Hyprland: 0.56.2، commit `efb50993780079460b0cbed1363e2166a2de1d9f`.
- المشروع عند البداية: HEAD `86bb4ec`، مع تعديلات إعدادات وواجهة موجودة/جارية ليست جزءًا من هذا العمل.
- الجرد الآلي أثناء الفحص: 593 ملف QML، و172 إعلان Timer، و187 Process، و253 Loader، و13 LazyLoader. هذه أعداد تعريفات في المصدر وليست أعداد كائنات عاملة في الجلسة.
- لم تكن هناك عملية Quickshell عاملة في بداية الفحص، ثم شُغلت النسخة المثبتة أثناء العمل. لذلك لا يوجد قياس خمول «قبل» يصلح لوصف بداية المهمة.
- عينة الجلسة اللاحقة قبل نشر النسخة النهائية من الخدمات: 18.63% من نواة واحدة، و1835 MiB RSS، خلال 20 ثانية. كانت هناك تطبيقات وتفاعلات أخرى وvisualizer مفعّل. هذه ليست جلسة اختبار مضبوطة.

عينة أخرى بعد نشر دفعة IPC وإعادة التحميل سجلت 4.14% CPU و1267 MiB RSS. لا أنسب الفرق كله للتحسينات: المقارنة تتضمن hot reload، واختلاف نشاط التطبيقات والمحتوى، ولا تضبط تسخين الكاش أو زمن عمر الجلسة.

ملفات الأدلة: `code-inventory.json`، `microbenchmarks.json`، `microbenchmarks-final.json`، `service-probe.json`، `session-before.json`، وملفات تدقيق اللوجات في هذا المجلد.

## 3. التجارب الفعلية

### 3.1 النقل إلى Hyprland

30 عينة دافئة لكل آلية، مع فاصل 30ms بين الطلبات، وقراءة `clients` فقط دون تحريك نوافذ أو تغيير workspaces:

| المسار | الوسيط ms | P95 ms |
|---|---:|---:|
| عملية `hyprctl clients -j` | 16.93 | 20.04 |
| اتصال Python مباشر، للمقارنة المعملية | 0.89 | 1.01 |

الفرق نحو 94.7% في زمن هذه العملية المحددة. التطبيق النهائي يستخدم `Quickshell.Io.Socket`، وليس Python في مسار IPC. وقد اختُبر هذا المكون فعليًا داخل Quickshell أمام Hyprland الحقيقي. لا نفترض أن رقم Python هو نفسه زمن QML؛ هو الدليل الذي برر تجربة إزالة العملية الخارجية.

Hyprland يحذر من أن request socket يعالج الاتصالات تزامنيًا. لذلك يفتح الكود اتصالًا لكل معاملة، ويرسل `j/<query>` و`flush()` فور الاتصال، ويغلق بمجرد اكتمال المستند. توجد مهلة وحد لحجم الرد. المصدر: [Hyprland IPC](https://wiki.hypr.land/ipc/).

### 3.2 تجربة لم تنجح واستُبدلت

| قارئ الحساسات | الوسيط ms | P95 ms |
|---|---:|---:|
| أوامر Bash القديمة المتزامنة للحساسات وGPU والقرص | 101.60 | 113.09 |
| Python جديد لكل عينة | 242.10 | 275.37 |
| Python مستمر: أول عينة، مرة واحدة | 217.68 | — |
| Python مستمر: عينات تالية، 30 عينة | 55.04 | 71.82 |

لم نعتمد تشغيل Python جديد لكل دورة لأنه كان أبطأ. النسخة النهائية عملية مملوكة للشِل تقرأ stdin وتنتج JSON واحدًا لكل طلب. لا تنفذ حلقة polling مستقلة؛ المؤقت في QML هو الذي يطلب العينة. تكلفة بدء المفسر تُدفع مرة لكل عمر خدمة، مقابل احتفاظ العملية بذاكرة خاصة بها.

المقارنة لها قيد: البديل النهائي يفصل `df` إلى مرة كل دقيقة، ويقرأ حرارة المعالج من sysfs، وقد تختلف دلالة الحرارة عن `Package id 0` القديم؛ القارئ يختار أعلى حساس CPU معروف في أول hwmon مناسب. هذه ليست قياسات حساسات متطابقة بتًا ببت. هي مقارنة تكلفة الحصول على المعلومات التي تعرضها الواجهة، مع الإفصاح عن اختلاف الآلية.

### 3.3 تحديثات متكررة داخل Quickshell

تم تشغيل نسخة HEAD ونسخة العمل في جذور Quickshell معزولة بلا نوافذ، وكل منهما يتصل بالمركّب الحقيقي، مع 25 طلب `updateAll()` بفاصل 200ms:

| المقياس | HEAD | التنفيذ المحسن |
|---|---:|---:|
| نشر قائمة النوافذ | 28 | 1 |
| نشر الشاشات | 28 | 2 |
| نشر workspaces | 28 | 1 |
| نشر active workspace | 28 | 1 |
| CPU للعملية فقط، ثانية | 0.97 | 1.02 |
| أعلى RSS مقاس، MiB | 224.68 | 227.70 |

أحداث البيئة وبداية التشغيل تفسر زيادة النشرات القديمة عن 25. النتيجة القوية هنا هي انخفاض إعادة نشر بيانات لم تتغير. العينة لا تثبت انخفاض CPU؛ بل الرقم المقاس أعلى قليلًا في البديل، ويستبعد CPU العمليات الفرعية. يلزم تكرار منضبط مع حساب شجرة العمليات قبل الادعاء بنسبة طاقة أو CPU.

## 4. ما تغير في قلب الخدمات

### HyprlandSnapshot وHyprlandData

كل نوع بيانات له طلب واحد جارٍ وعلامة طلب تالٍ واحدة. تبدأ نافذة التجميع عند أول حدث ولا يعيد كل حدث تشغيلها؛ لذلك تيار مستمر من الأحداث لا يؤخر التحديث إلى الأبد. النافذة 16ms، وهي تأخير تجميع مطلوب وليست ضمانًا لزمن إطار.

- النقل الأصلي عبر Socket عند توفر مسار الجلسة، و`hyprctl` إذا لم يتوفر المسار.
- لا تتحول أعطال socket تلقائيًا إلى مسار Process؛ يحتفظ النظام بآخر snapshot وتعيد الأحداث التالية المحاولة. fallback هنا متعلق بتوفر المسار وليس كل فشل.
- التحقق من نوع JSON، والاحتفاظ بآخر بيانات سليمة عند الفشل أو الرد التالف.
- مهلة 2000ms لكل طلب، وحد رد 16 مليون وحدة نصية تقريبًا؛ هذا ليس حدًا دقيقًا لكل الذاكرة المؤقتة داخل Qt.
- بيانات جديدة فقط هي التي تولد إشارة snapshot. المقارنة تسلسل JSON؛ اختلاف ترتيب الحقول يمكن أن يسبب نشرًا إضافيًا، ولا ندّعي canonical JSON.
- اتصال جديد لكل طلب، بما في ذلك بعد فشل الاتصال، لتجنب بقاء QLocalSocket في حالة غير قابلة لإعادة الاستخدام.
- تجميع البايتات بـStdioCollector قبل اعتماد النص، للحفاظ على العربية والإيموجي عند تقسيم UTF-8 بين حزم.
- الإغلاق عند اكتمال JSON يمنع سيل `PeerClosedError` في الاتصالات الناجحة. الردود الجزئية/التالفة تُحسم عند الإغلاق أو المهلة.
- تحديث layers عند أحداث فتحها وإغلاقها؛ وعدم عمل تحديث شامل بسبب `activelayout` أو `submap` أو `bell`.
- تحديث حالة workspace عند فتح/غلق/نقل النوافذ أو تغير التركيز، للحفاظ على counts وlastwindow.
- `HyprlandBackend` أصبح يربط كل خاصية بمصدرها بدل تشغيل refresh يعيد بناء الجميع عند تغير أي مجموعة.

راجعت مصدر [datastream.cpp](https://github.com/quickshell-mirror/quickshell/blob/master/src/io/datastream.cpp) و[socket.cpp](https://github.com/quickshell-mirror/quickshell/blob/master/src/io/socket.cpp). المصدر المنشور master ليس بالضرورة مطابقًا للحزمة، ولذلك استُخدمت اختبارات على الملف التنفيذي المثبت للتحقق. مثلًا `trimEnd` لم يكن متاحًا في محرك QML المحلي واستُبدل بـ`trim`.

### ResourceUsage وDateTime

`/proc/meminfo` و`/proc/stat` و`/proc/uptime` تُقرأ عبر FileView دون `cat/awk/grep`. التحليل يحدث في `onLoaded` بعد اكتمال القراءة، لأن `reload(); text()` قد يرجع البيانات السابقة وفق [توثيق FileView](https://quickshell.org/docs/v0.3.1/types/Quickshell.Io/FileView/).

معادلة CPU تضم steal، وتتعامل مع iowait كوقت غير منفذ، ولا تضيف guest مرتين. أول عينة تؤسس baseline، وتُرفض البيانات غير الصالحة. سجلات التاريخ تُنشر مرة واحدة لكل عينة بدل نشر ثم تعديل القائمة بـshift.

الحساسات تُقرأ من sysfs خارج خيط الواجهة، مع fallback محدود الزمن إلى nvidia-smi. لا تُقتل العملية وتُعاد كل tick. يوجد منع طلبين متداخلين وwatchdog وإعادة محاولة على دورة المؤقت التالية. أُضيف ResourceUsageLease إلى المستهلكين التسعة: يبدأ القياس عند أول مستهلك ظاهر، ويتوقف بعد اختفاء آخر مستهلك، ويعاد تأسيس baseline للـCPU عند العودة. التحقق يشمل رؤية النافذة نفسها، لا شفافية العنصر وحدها. يحفظ التاريخ المتاح لكنه لا يجمع تاريخًا خلال فترة عدم وجود مستهلك ظاهر.

`df` أصبح أمرًا مباشرًا مرة كل دقيقة؛ عداد uptime أيضًا مرة كل دقيقة لأنه يعرض دقائق. Widget uptime صار يشترك في DateTime بدل قارئ uptime إضافي، وقراءة loadavg تستخدم onLoaded بدل إشارة مراقبة ملف غير مناسبة. تم تصحيح عرض CPU في InfoStrip من قيمة 0..1 إلى نسبة 0..100.

## 5. تطبيق ملاحظات الصور

| الملاحظة | التقييم والتطبيق |
|---|---|
| أنواع محددة بدل var | صحيحة عند ثبات النوع. تحول defaultFont إلى string، مع الإبقاء على var للكائنات والدوال والخرائط التي تحتاجه فعلًا. |
| visible بدل opacity | الإخفاء يوقف الرسم، لكنه لا يوقف كل bindings والمؤقتات. لا نحذف أنيميشن الخروج؛ نفصل عمر المحتوى أو نشاط المؤقت عن الشفافية. |
| anchors.fill | مناسب للملء الكامل، وليس بديلًا آليًا عن Layout أو أبعاد جزئية. أغلب الحاويات الأساسية تستخدمه بالفعل؛ لا تغيير تجميلي شامل بلا قياس. |
| ListView وclip وcacheBuffer | لا نزيل clip من viewport يحتاجه. لا نضع clip أو shaders لكل delegate بلا سبب. cacheBuffer الأكبر يستهلك ذاكرة؛ لا قيمة موحدة لكل القوائم. |
| الصور async/cache/smooth | StyledImage يعمل asynchronous بالفعل، وCarousel يضبط cache وsourceSize. cache ليس دائمًا مكسب ذاكرة، وsmooth مهم عند تصغير الصور. لم يُعطل التنعيم عالميًا. |
| PlainText | طُبق على نصوص موارد/شريط واضحة لا تحتاج HTML. لم نغير النصوص الغنية والإشعارات عالميًا كي لا نكسر التنسيق. |
| تقليل المؤقتات والعمليات | منفذ في الموارد وuptime وIPC، مع فصل الترددات بدل إبطاء كل الواجهة. |
| قراءة proc/sys مباشرة | منفذة: proc بـFileView، والحساسات عبر قارئ مستمر خارج GUI لأن hwmon قد يحجب القراءة. |
| lazy loading | الشريط الأيسر ينشئ محتواه عند أول فتح. كل صفحة تُنشأ عند أول زيارة وتُحفظ بعدها، وتملكها حاوية تدير عمرها. باقي الأنظمة مثل lock/polkit لا تُؤجل عشوائيًا. |
| حلقة مراقبة التطبيقات | فحصنا البلاغ والمسار المحلي؛ لم نجد نمط AppLibrary + bash -lc الموصوف. فهرس AppSearch يستخدم DesktopEntries مباشرة. أزلنا إزالة التكرار التربيعية واستبدلناها بـSet في مرور واحد. |

بلاغ [Omarchy #6806](https://github.com/omacom/omarchy/issues/6806) يصف تطبيقًا محددًا يبدأ login shell من scans، وليس عيبًا مثبتًا في كل شِل. وبلاغ [Quickshell #757](https://github.com/quickshell-mirror/quickshell/issues/757) يبرر مراقبة معدلات rescans وحجم اللوج؛ وجود بلاغ لا يثبت تسببه في الاستهلاك المحلي.

توصية LazyLoader تحتاج تدقيقًا: `active: true` قد يفرض الإكمال تزامنيًا، و`loading: true` يمكن استخدامه للتحضير غير المتزامن، وقراءة item قد تفرض الإكمال. كما أن إعادة التحميل وVariants لها قيود موثقة. لذلك لم نضع `active: true` على كل popup ثم نعتبره تحسينًا. المصادر: [LazyLoader](https://quickshell.org/docs/v0.3.1/types/Quickshell/LazyLoader/)، [Qt SwipeView](https://doc.qt.io/qt-6/qml-qtquick-controls-swipeview.html)، [Qt Quick performance](https://doc.qt.io/qt-6/qtquick-performance.html).

## 6. اللوجات وما يمكن استنتاجه

فُكّت ملفات qslog المتاحة وفُحصت سجلات الجلسة وملفات crash القديمة. امتداد `log.qslog.log` في مجلد crashes لا يعني نصًا؛ بعض الملفات ثنائية، وبعضها فارغ. ملفا JSON للتدقيق يذكران المصدر وعدد الأسطر والمشاكل الأكثر تكرارًا. السجلات الثنائية والنصية لنفس الجلسة قد تحتوي الأحداث نفسها؛ لا نجمعهما باعتبارهما حادثتين.

ظهرت قديمًا binding loops في ToolbarTabBar وRevealer، وrecursive rearrange في ConfigTextArea، وnull workspace، ومشاكل PipeWire وصور مفقودة. بعضها في نسخة قديمة من Horizons وبعضها في شِل مختلف؛ لم ننسب كل crash إلى الكود الحالي، ولا يمكن تحديد سبب SIGSEGV من تحذيرات سابقة وحدها دون backtrace.

السجل الحالي أظهر كذلك فشل تركيز نافذة خارج مجموعة workspaces مكتملة، ومرجع `filterField` في محدد الخلفيات، وتحذيرات ShaderEffect. وبعد hot reload ظهرت تحذيرات polkit عن تسجيل موجود وأن بعض العناصر ما زالت قيد الإنشاء عند تدمير المحرك. هذه عيوب متبقية/قيود reload، وليست نتائج نجحت فيها هذه الحزمة. يجب فصل تشخيص صحتها عن قياس الأداء.

## 7. الاختبارات وإعادة التجربة

من جذر المستودع:

```bash
python3 -m unittest discover -s shell/tests -p test_performance_runtime.py -v
python3 shell/scripts/performance/benchmark.py --samples 30 --output /tmp/horizons-bench.json
python3 shell/scripts/performance/service_probe.py
python3 shell/scripts/performance/profile_session.py PID --seconds 20 --output /tmp/horizons-session.json
```

اختبارات runtime تستدعي Quickshell المثبت فعلًا، مع جذور مؤقتة وخدمات مصغرة. تغطي burst، وتيار الأحداث المستمر، والمهلة، وفشل الاتصال، وJSON التالف، وUTF-8 بايتًا بايتًا، وقراءة Hyprland الحية، والحساسات/CPU/RAM/القرص، وتحميل صفحات sidebar مرة واحدة مع حفظ الصفحة عند العودة إليها. الاختبار المصغر للsidebar يستخدم بدائل لمحتويات الصفحات؛ لا يعادل اختبار كل أدوات AI/ترجمة في الجلسة الحقيقية.

توجد اختبارات قديمة تفحص أسماء داخل التنفيذ. نُقلت مسؤولية اختبار debounce وparse إلى اختبارات السلوك الجديدة، مع الحفاظ على الاختبارات الأخرى. نجحت المجموعة الكاملة: 48 اختبارًا، منها 10 اختبارات runtime؛ التفاصيل في `validation.json`؛ لا ينبغي اعتبار نجاح اختبارات الأداء نجاحًا تلقائيًا لكل اختبارات المستودع المتغير أثناء العمل.

## 8. التكامل مع dotfiles والتراجع

إقلاع الشِل في dotfiles يستخدم الآن `qs -n` لمنع تشغيل نسخة مكررة لنفس config/display. لا نقلّل blur أو نعطل animations عالميًا لإخفاء كلفة الخدمات، ولا نضع متغيرات QSG غير مقاسة، ولا نعيد تشغيل Hyprland.

نُشرت الدفعة النهائية في 21 ملفًا من الشِل المثبت، مع نسخة رجوع. أُعيد فتح الشريط الأيسر وإغلاقه مرتين بعد إصلاح ملكية المحتوى؛ نافذة الفحص الأخيرة بعد reload لم تسجل تحذيرات أو أخطاء. هذه ملاحظة اختبار قصيرة وليست ضمانًا لغياب كل أخطاء الجلسة. تعديل execs.lua اجتاز luac وموجود في المستودع؛ لم تُعد جلسة Hyprland للتجربة.

التحديث المثبت يتم بملفات محددة ونسخة رجوع، وليس بإعادة تشغيل installer على كل dotfiles. مسارات الملفات ونسخ الرجوع موجودة في `deployment*.json`. لاسترجاع دفعة: انسخ فقط الملفات المدرجة من backup إلى مساراتها في مجلد التثبيت، ثم اترك مراقبة Quickshell تعيد التحميل. الملفات الجديدة التي لم يكن لها backup يجب التعامل معها وفق manifest؛ لا تحذف مجلد الإعدادات كله.

## 9. خارطة العمل المتبقي للوصول إلى إحساس DE أصلي

1. **قياس إطارات حقيقي**: QML Profiler + render timing، جلسات منفصلة باردة ودافئة، 30 دورة فتح/إغلاق launcher وsidebar وoverview، على كل شاشة وscale. قياس P50/P95/P99 للمدخل إلى أول إطار، وليس زمن IPC فقط.
2. **عمر الخدمات حسب الطلب**: توسيع اشتراكات الرؤية المنفذة في ResourceUsage إلى NetworkStats وMPRIS position، وإيقاف work أثناء قفل/DPMS وتغطية الخلفية، مع عينة جديدة عند العودة. نحتاج عقودًا واضحة لمن يريد history مستمرًا ومن يريد العرض فقط.
3. **ذاكرة الرسومات**: قياس صور wallpaper/thumbnails وShaderEffectSource وحجم textures منفصلًا عن RSS. تثبيت sourceSize على فئات أحجام لتجنب فك الصورة مع كل بكسل resize، وإخلاء thumbnails البعيدة مع الحفاظ على cache للأصول المشتركة.
4. **الشاشات والـworkspaces**: اختبار hotplug، وإعادة الترتيب، والشاشات المختلفة في scale، وnamed/special workspaces، وحل خطأ incomplete all-screens workspace set. التغييرات الحالية تحتفظ بفلتر workspace IDs القديم 1..100؛ لم يُوسع البروتوكول إلى كل named workspaces في هذه الحزمة.
5. **ضبط startup**: مراحل أساسية للbar/lock/notifications/polkit، ثم الخدمات غير الضرورية، مع ميزانية مللي ثانية قابلة للقياس. لا نقيس `Configuration Loaded` باعتباره اكتمال أول إطار لكل panels.
6. **استقرار reload**: دورة حياة تسجيل polkit وملكية الكائنات الديناميكية، واختبار 20 reload بذاكرة مستقرة. انخفاض الذاكرة بعد reload وحده لا يثبت إصلاح leak.
7. **C++ عند ثبوت الحاجة**: إذا أظهر profiler أن JSON/خرائط JavaScript أصبحت bottleneck بعد إزالة forks والتكرار، يُبرر نموذج C++ ثابت الهوية مع تحديث صفوف محددة، أو توسيع Quickshell.Hyprland upstream. لا نضيف ABI وصيانة build جديدة قبل دليل.

العينة الأخيرة بعد دفعة التحسينات الموسعة وفي جلسة أُعيد تشغيلها أثناء العمل كانت 16.24% CPU و1223.55 MiB RSS في نهاية 20 ثانية. اختلافها عن عينة 4.14% السابقة يؤكد أن الحمل غير ثابت؛ لم تثبت نسبة عامة لتحسن CPU.

معيار القبول المقترح، لا نتيجة مقاسة الآن: بقاء المهام التفاعلية ضمن ميزانية الشاشة (16.7ms عند 60Hz أو 8.3ms عند 120Hz)، وعدم وجود polling سريع من واجهة مغلقة، وعدد عمليات فرعية قريب من الصفر في الخمول، وغياب نمو مستمر للذاكرة بعد دورات الفتح والإغلاق.
